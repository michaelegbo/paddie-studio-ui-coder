01 / Executive summary

What Paddie Studio is built to do.

Paddie Studio is a desktop product for building software with AI while keeping the work visible. It combines the proven opencode agentic coding engine with Paddie-owned Studio tools for templates, inspiration references, workflow builder context, previews, and native Autopilot orchestration.

02 / Product features

The studio becomes the control room.

The main product idea is simple: keep the coding agent, the project, the design reference, the workflow, and the preview in the same place. Users can move between normal chat, Studio tools, and Autopilot runs without losing the workspace context.

Paddie Chat

AI coding stays familiar.

Normal chat and code-builder flows remain powered by opencode. Paddie adds context and Studio tools around that flow instead of replacing the core chat experience.

Templates

Design references become build context.

The Studio template system turns polished UI starters into visible, attachable implementation references that can be adapted across project stacks.

Inspiration

Public websites become design signals.

Public pages can be captured as sanitized references for layout, hierarchy, color, typography, and motion intent without copying private assets or authenticated content.

Workflow Builder

Saved flows become code integrations.

Workflow graphs and generated client code can be attached to coding tasks so the app can wire product logic without manually rebuilding the flow.

Preview

Output is checked where it runs.

Paddie can detect local project previews, inspect browser output, surface errors, and feed failures back into the build loop.

Autopilot

Complex tasks become managed runs.

Autopilot plans work, breaks goals into tasks, coordinates scoped opencode worker sessions, verifies output, and hands results back to the user.

03 / Technology architecture

The technology is layered, not forked.

Paddie Studio is built as an additive desktop and Studio layer around opencode. The architecture keeps provider configuration, sessions, shell execution, permissions, and coding tools in the opencode runtime, while Paddie owns the Studio-specific UI, adapters, context packaging, and orchestration views.

Desktop app Tauri packages the local Windows desktop experience and sidecar runtime.
App UI Solid, TypeScript, and Paddie Studio components render chat, Studio, and workbench surfaces.
opencode Sessions, prompts, tools, shell execution, permissions, providers, and model routing.
Paddie APIs Templates, workflow catalog, generated clients, account state, and Studio resources.
Preview loop Local server detection, browser inspection, console checks, screenshots, and validation output.
04 / Native Autopilot

Autopilot turns goals into managed execution.

Paddie Native Autopilot is the autonomous layer inside Studio. It uses the currently selected opencode model and provider, creates scoped worker sessions, keeps normal chat isolated, and shows live activity as the run moves from planning to implementation, verification, preview, iteration, and handoff.

Plan

Break the request into tasks

Autopilot keeps one overall goal, creates a task queue, and shows what is pending, active, done, or blocked.

Execute

Use scoped opencode workers

The worker edits files, runs commands, uses templates or workflows, and reports progress through the run timeline.

Verify

Test, preview, and hand off

Checks and browser feedback are collected, failures can be fed back into the loop, and the final result is summarized.

06 / Safety model

Power stays visible and bounded.

The product is designed so advanced Studio features do not destabilize the normal coding path. Paddie features are optional, scoped to selected workspaces, and built around explicit context, approval, and upstream-safe integration boundaries.

Isolation

Dedicated sessions for autonomous work.

Autopilot creates scoped worker sessions instead of typing into the normal chat composer. Attaching a run to chat is optional discussion context, not the execution path.

Approvals

Risky actions require explicit consent.

Destructive file changes, git push or release, deploys, credential use, payments, publishing, and actions outside the workspace require approval before execution.

Provider reuse

The selected model stays the source of intelligence.

Paddie does not create a second credential system. Autopilot and chat use the provider, model, agent, and variant already selected in the app.

Upstream-safe

Paddie features sit at clear boundaries.

Studio tools are implemented as additive adapters around opencode so upstream chat, sessions, tools, and provider behavior remain practical to sync.

07 / Closing note

Paddie Studio turns AI software creation into a visible studio workflow: bring in the right design, attach the right workflow, run the right model, preview the result, and keep every autonomous step traceable.
