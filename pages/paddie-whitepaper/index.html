01 / Executive summary

What changed from stable to beta.

The stable build proves the Paddie desktop shell, Studio surface, templates, workflow embedding, and upstream opencode foundation. The beta builds on that base with Paddie Native Autopilot: an additive orchestration layer that uses opencode sessions and tools instead of introducing a second AI runtime.

02 / Product thesis

The studio becomes the control room.

Paddie Studio is not a separate fork of the coding agent. It is a product layer around opencode that gives users visual tools, reusable templates, workflow context, browser feedback, and autonomous run state while keeping normal chat and code-builder behavior intact.

Templates

Design references become build context.

The Studio template system turns polished UI starters into visible, attachable implementation references that can be adapted across project stacks.

Workflow Builder

Saved flows become code integrations.

Workflow graphs and generated client code can be attached to coding tasks so the app can wire product logic without manually rebuilding the flow.

Inspiration

Public websites become motion references.

Public pages can be captured as sanitized design references, preserving visible layout, typography, color, and motion intent without copying private assets.

03 / Native architecture

Autopilot uses opencode as the harness.

The beta direction removes OpenClaw from the execution path. Autopilot becomes a Paddie-owned controller that starts scoped opencode worker sessions, uses the selected model and provider, and listens for progress, tool, shell, status, and handoff events.

Studio User goal, selected workspace, templates, workflows, preview context.
Controller Plans the run, owns state, queues tasks, enforces approval boundaries.
opencode session Dedicated worker session using the current agent, model, provider, and variant.
Tools Files, commands, tests, preview detection, browser checks, and task markers.
Handoff Changed files, checks, preview status, artifacts, blockers, and residual risks.
04 / Beta release

The beta is about controlled autonomy.

Paddie Native Autopilot is designed to do real work while staying visible, stoppable, and isolated from normal chat. The user sees a plan before execution, live activity after the run starts, and a final handoff when the worker finishes.

05 / Safety model

Autonomy stays additive and upstream-safe.

Paddie-specific features should sit around opencode, not replace it. Normal chat, model/provider setup, and code-builder behavior must work unchanged when Autopilot is disabled or unused.

Isolation

Dedicated sessions for autonomous work.

Autopilot creates scoped worker sessions instead of typing into the normal chat composer. Attaching a run to chat is optional discussion context, not the execution path.

Approvals

Risky actions require explicit consent.

Destructive file changes, git push or release, deploys, credential use, payments, publishing, and actions outside the workspace require approval before execution.

06 / Closing note

Paddie Studio turns coding assistance into a visible studio workflow: plan first, act in scoped sessions, verify in public, and hand the result back clearly.
